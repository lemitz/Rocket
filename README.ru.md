<h1 align="center">Rocket</h1>

<p align="center">
  Передача файлов между Windows-ПК и Android-телефоном по Wi-Fi: выбрал файлы, провёл слайдер, ракета полетела.<br>
  Один экран с ракетой и парой кнопок на обоих устройствах. Без аккаунтов, без облака, без телеметрии, без лишнего.

Rocket делает одно: отправляет выбранные на одном устройстве файлы на другое, максимально напрямую. Выбираешь файлы, двигаешь слайдер **«Поехали!»** вправо, элементы управления гаснут, и ракета взлетает. Когда последний файл долетел и проверен, ракета улетает за верхний край экрана, а из дыма появляются цифры: файлы, объём, время, средняя скорость. Вот и весь интерфейс, и он одинаковый на ПК и на телефоне. Всё, что нужно один раз (какой ПК, какая папка, проверки), спрятано за шестерёнкой.

Это два маленьких приложения, а не фреймворк: один Windows-exe на Go только со стандартной библиотекой и приложение для Android на Kotlin только с платформенными API, без Compose, AndroidX и сторонних библиотек.

## Возможности

**Отправка**
- **Телефон → ПК:** выбери файлы в приложении (или «Поделиться» из Галереи и любых других приложений), проведи слайдер. Файлы окажутся в папке Windows `Downloads` или в выбранной тобой папке
- **ПК → телефон:** выбери файлы в окне (или перетащи их в окно), проведи слайдер, и телефон сам скачает их, пока Rocket открыт на его экране. Файлы читаются там, где лежат, ничего не копируется во временную папку
- Несколько файлов за раз (до 256 с ПК), файлы до 1 ТиБ, одно соединение на пачку. Ничего не перезаписывается: совпадение имени превращается в `имя (1).расш`
- Каждый файл проверяется CRC32C и сначала пишется во временный файл, поэтому оборванная или отменённая передача не оставляет недокачанный файл
- Итоговая карточка показывает, сколько файлов пришло, какой объём, сколько заняло времени и среднюю скорость. ПК считает файл доставленным только после подтверждения телефона
- Два телефона могут отправлять на один ПК одновременно, их статистика не смешивается

**Поиск друг друга**
- Никакого сопряжения и ввода IP: телефон сам находит ПК в сети, а ПК видит каждый телефон с открытым Rocket
- Устройство одно: Rocket выбирает его и запоминает. Несколько: один раз выбираешь на отправителе одним касанием, и это тоже запоминается
- Если ПК получил новый IP-адрес (DHCP), телефон снова находит его по ID без вопросов
- Если поиск не работает в твоей сети (например, гостевой Wi-Fi с изоляцией клиентов), введи IPv4-адрес ПК в настройках телефона

**Ракета**
- Ракета нарисована по иконке приложения; одна и та же сцена работает на обоих устройствах: ракета дрожит и взлетает, мимо летят штрихи скорости, за ней тянется след пламени, она улетает за верхний край, собирается дым, и из него поднимается карточка со статистикой
- Отрисовка идёт в ритме самого дисплея (Android `postInvalidateOnAnimation` плюс запрос высокой частоты, Windows Direct2D со vsync); неподвижный экран не перерисовывается вообще
- Тёмный интерфейс, сглаженный при любом масштабе. Русский или английский по языку системы
- Android: тематическая монохромная иконка и вибро-отклик на слайдер и результат; Windows: тёмная рамка окна и DPI для каждого монитора

**Настройки (шестерёнка)**
- **ПК:** папка приёма (сменить, открыть), адреса ПК, проверка связи (сервер, поиск устройств и брандмауэр Windows, с кнопкой «Исправить», которая один раз запрашивает разрешение) и недавно виденные телефоны
- **Телефон:** какой ПК выбран (найти или ввести адрес), папка приёма (системная `Download` или любая выбранная), кнопка «Проверить» с задержкой до ПК, имя и версия телефона

**Всё остальное**
- Один портативный exe на Windows и один APK на Android; без установщика, без службы, без фоновых процессов. Закрыл окно, и всё остановилось
- Без телеметрии и без выхода в интернет: Rocket общается только с устройствами в твоей локальной сети
- На Android не запрашивается широкий доступ к хранилищу: файлы читаются через системный выбор и сохраняются в `Download` через MediaStore (или в папку, к которой ты дал доступ)

> **Без шифрования и паролей.** Rocket сделан для сети, которой ты доверяешь, например для домашнего Wi-Fi. Любой в этой сети может отправить файлы на твой ПК. Не используй его в публичном Wi-Fi. См. [SECURITY.md](SECURITY.md).

## Как пользоваться

1. Запусти `Rocket-<версия>-win-x64.exe` на ПК и установи `Rocket-<версия>-android.apk` на телефон. Держи оба открытыми, пока передаёшь.
2. **Телефон → ПК:** на телефоне нажми «Выбрать файлы», проведи слайдер **«Поехали!»**
3. **ПК → телефон:** на ПК нажми «Выбрать файлы» или перетащи файлы в окно, убедись, что телефон показан в строке «На …», проведи слайдер **«Поехали!»** Телефон должен быть открыт с включённым экраном.

Проведи слайдер вправо достаточно далеко (примерно на 85%) и отпусти; если отпустить раньше, слайдер вернётся назад. «Отмена» тихо появляется под летящей ракетой на телефоне, и кнопка «Назад» тоже отменяет.

## Установка

Скачай файлы со страницы [Releases](https://github.com/lemitz/Rocket/releases):

- **Windows:** `Rocket-<версия>-win-x64.exe`, ничего устанавливать не нужно. В первый раз SmartScreen может предупредить о неподписанном приложении: «Подробнее» → «Выполнить в любом случае». Windows 10 или 11, 64 бита.
- **Android:** `Rocket-<версия>-android.apk`, открой на телефоне и разреши установку из браузера или файлового менеджера. Android 14 и новее.
- `SHA256SUMS.txt`, контрольные суммы. В PowerShell: `Get-FileHash .\Rocket-0.2.0-win-x64.exe -Algorithm SHA256`.

**Брандмауэр Windows:** ПК должен принимать подключения с телефона. При первом запуске открой шестерёнку и нажми **«Исправить»** рядом с «Брандмауэр» (Windows один раз попросит разрешение) либо выполни `rocket.exe firewall install` в терминале администратора. Команда открывает TCP 42070 и UDP 42069 только для **частного** сетевого профиля и локальной подсети; Rocket сам никогда не меняет правила брандмауэра. Проверь также, что сетевой профиль ПК «Частная» и что в Wi-Fi нет изоляции клиентов.

Rocket не обновляется сам. APK, подписанные разными ключами, нельзя ставить друг поверх друга, см. [Релизы](#релизы), если собираешь свои.

## Разработка

Требования: [Go](https://go.dev/dl/) 1.25+ и, для приложения на телефоне, JDK 21 и Android SDK (API 36). Больше ничего, устанавливать пакеты не нужно.

```bash
go vet ./...
go test -race ./...                    # протокол, передачи, очередь, автомат состояний окна
go run ./cmd/rocket                    # приложение для ПК (Windows)
go run ./cmd/rocket daemon             # только сервер, в консоли, для диагностики
cd android && ./gradlew :app:assembleDebug     # gradlew.bat в Windows
```

Окно можно просмотреть, не открывая его: `ROCKET_SNAPSHOT_DIR=out go test ./internal/desktop -run TestRenderStates` пишет PNG каждого состояния экрана на английском и русском. В [docs/BUILD_TEST.md](docs/BUILD_TEST.md) описана и сквозная проверка с эмулятором Android, а в [docs/OPEN_ISSUES.md](docs/OPEN_ISSUES.md) перечислено, что известно как недоделанное или непроверенное.

## Сборка

```powershell
./scripts/build.ps1                  # тесты, rocket.exe и APK в dist/ вместе с SHA256SUMS.txt
./scripts/build.ps1 -SkipTests       # быстрее
./scripts/build.ps1 -Offline         # Gradle без сети (нужен прогретый кэш)
```

Версия — одна строка в [`VERSION`](VERSION): она попадает в `rocket.exe version`, `versionName` APK и тег релиза. Иконка — `assets/icon-source.png`; `go run ./tools/genassets` превращает её в спрайт ракеты, значки лаунчера Android и Windows `.ico`.

## Релизы

Всё делает [`build.yml`](.github/workflows/build.yml):

- **Pull request в `main`:** форматирование, `go vet`, `go test -race`, сборка exe и APK, которые прикладываются к запуску как артефакты, чтобы изменение можно было попробовать до слияния. В запуске написано, опубликует ли слияние релиз.
- **Слияние в `main`:** та же сборка, затем публикуется **GitHub Release `v<VERSION>`** с `Rocket-<версия>-win-x64.exe`, `Rocket-<версия>-android.apk` и `SHA256SUMS.txt`; текстом служит [`RELEASE_NOTES.md`](RELEASE_NOTES.md) плюс список влитых pull request'ов. Если такой тег уже есть, ничего не публикуется, поэтому обычные pull request'ы только собираются.
- **Кнопка «Run workflow»:** собирает любую ветку, ничего не публикует.

Чтобы выпустить релиз, положи в pull request новую версию в `VERSION` и подходящий `RELEASE_NOTES.md`, начинающийся с `# Rocket v<версия>` (оба файла проверяет `./scripts/check-release.ps1`, workflow тоже его запускает). Слей, и релиз появится.

**Подпись APK.** Без секретов релизный APK подписывается одноразовым отладочным ключом: он работает, но каждый релиз придётся удалять перед установкой следующего. Один раз сделай как надо:

```powershell
./scripts/make-keystore.ps1          # создаёт ключ вне репозитория и печатает четыре секрета
```

Добавь `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD` в *Settings → Secrets and variables → Actions* и сохрани копию ключа: потерянный ключ значит, что для обновления пользователям придётся удалять приложение.

## Структура проекта

```
VERSION                    версия всего
assets/                    icon-source.png (иконка), icon-circle.png
tools/genassets/           конвейер иконки: спрайт, значки лаунчера, .ico (только стандартная библиотека)
scripts/                   build.ps1, check-release.ps1, make-keystore.ps1
cmd/rocket/                точка входа, CLI (daemon, firewall, settings), ресурсы Windows (иконка, манифест)
internal/
  wire/                    кадры протокола
  server/                  TCP-сессии: put, poll, offer-get, offer-done, статистика передач
  outbox/                  файлы, адресованные ПК телефонам (хранятся в памяти)
  fsx/                     временные файлы, безопасные имена, публикация без перезаписи
  discovery/               UDP-ответ на «кто здесь»
  config/                  настройки, ID ПК, папка Downloads в Windows
  desktop/                 окно ПК: программный рендер, сцена, настройки, презентер Direct2D
android/app/               приложение телефона: LaunchView (сцена), MainActivity, SettingsPanel, протокол, хранилище
docs/                      HANDOFF, ARCHITECTURE, PROTOCOL, BUILD_TEST, OPEN_ISSUES (на русском)
.github/                   workflow сборки и релиза, шаблоны issue и pull request
```

Разделение ролей сделано намеренно: ПК всегда слушающая сторона, а телефон открывает каждое соединение. Чтобы отправить файл *с* ПК, ПК кладёт в память ссылку на файл и сообщает о нём телефону при следующем запросе телефона (примерно раз в секунду, пока Rocket открыт); затем телефон скачивает файл. Просмотра чужих файлов нет, и нет команды получить произвольный путь. Формат передачи описан в [docs/PROTOCOL.md](docs/PROTOCOL.md).
