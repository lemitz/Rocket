# Rocket — передача файлов между Windows и Android

**Два действия на устройстве-отправителе: выбери файлы → нажми «Поехали» (Launch).** Не нужно просматривать файлы другого устройства. Пока передача идёт, ракета взлетает; после успешной проверки и сохранения улетает вверх, а на её месте появляются количество файлов, объём, время и средняя скорость.

## Как пользоваться

1. Запусти `rocket.exe` на каждом ПК — двойной клик открывает окно Rocket. Не закрывай его, пока нужен обмен. Установи `android/app/build/outputs/apk/debug/app-debug.apk` на телефоны и **держи Rocket открытым на принимающем телефоне**.
2. **Телефон → ПК:** на телефоне один раз выбери нужный ПК через «ПК и папка приёма» (Discover или IP); приложение запомнит выбор. Выбери **файлы на телефоне** (можно через «Поделиться» из Галереи), нажми «Поехали». Они сохранятся в системной Windows Downloads либо в папке, выбранной в окне ПК.
3. **ПК → телефон:** на ПК нажми «Выбрать файлы» и выбери **локальные файлы ПК**; выбери один из открытых телефонов в списке; нажми «Поехали». Телефон сам проверяет наличие подготовленных файлов, скачивает их в системную `Download` или свою настроенную папку и показывает подтверждение. ПК остаётся слушателем, телефон инициирует TCP-соединения. Исходные файлы ПК не копируются в Downloads только ради отправки.

Для сети с двумя ПК и двумя телефонами: выбор адресата делается **на отправителе**. На каждом ПК видны только недавно открытые телефоны; если телефон не появился, открой Rocket на нём, выбери этот ПК в настройке телефона и обнови список телефонов на ПК. Если DHCP сменил IP ПК — открой настройки телефона и заново найди нужный ПК. Получателю не нужно выбирать файл отправителя.

**Ограничения:** во время ПК→телефон Rocket должен быть открыт на телефоне с включённым экраном. После отмены или ухода приложения в фон передача останавливается. Если подтверждение получения потеряно, повторная попытка может создать файл с суффиксом `(1)`; завершённые файлы не перезаписываются. Файлы с неизвестным размером у Android-провайдера пока не отправляются; произвольная папка телефона зависит от SAF-провайдера и не везде обещает атомарное переименование. Два телефона могут передавать одновременно — статистика каждого TCP-сеанса не смешивается.

## Настройки и диагностика

- Windows: папка приёма по умолчанию — текущая системная Downloads (`FOLDERID_Downloads`, учитывает перенаправления). Изменяется кнопкой в окне ПК; новые подключения используют новый путь, текущие завершаются по прежнему. Команды диагностики: `rocket.exe help`, `rocket.exe settings show`, `rocket.exe daemon` (консоль вместо окна).
- Android: папка по умолчанию — системная `Download` через MediaStore. В настройках Rocket можно выбрать другую папку системным диалогом или вернуться к Downloads. Доступ ко всем файлам не требуется.
- Если телефон не обнаруживает ПК, проверь одну локальную сеть, отсутствие «гостевой изоляции» Wi-Fi и профиль сети Windows **Private**. На **каждом ПК** один раз из терминала администратора запусти `rocket.exe firewall install`: это открывает TCP `42070` и UDP `42069` только для профиля Private и адресов LocalSubnet. При обычном запуске Rocket правила брандмауэра не меняет.
- **Без TLS, паролей и аутентификации по твоему требованию.** Используй только доверенную LAN: устройства с доступом в неё могут пытаться отправлять файлы и имитировать устройства. Список всех файлов Downloads больше не выдаётся протоколом. Временные `.part` проверяются CRC32C и публикуются после записи/закрытия; CRC32C не является криптографической защитой.

## Сборка и частота анимации

Go (без внешних пакетов): `go test -race ./...`, `go vet ./...`, `go build -trimpath -ldflags='-s -w' -o rocket.exe ./cmd/rocket`. Android SDK `Z:\SDK`: `cd android`, `gradlew.bat :app:assembleDebug --offline --no-daemon`.

Интерфейс следует языку ОС: RU или EN, иначе EN. Иконку предоставит пользователь позднее. Android запрашивает кадры через `postInvalidateOnAnimation()` и высокую частоту экрана при полёте; Windows использует Direct2D `D2D1_PRESENT_OPTIONS_NONE`, не устаревший `WM_TIMER`. Системную частоту монитора не меняем, статичный экран не перерисовывается непрерывно. Ни одна ОС не гарантирует 120 **показанных** кадров/с под любой нагрузкой: на реальных realme и Nothing это ещё предстоит измерить [Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline). [Android View/ARR](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate), [Windows Direct2D present options](https://learn.microsoft.com/en-us/windows/win32/api/d2d1/ne-d2d1-d2d1_present_options).
