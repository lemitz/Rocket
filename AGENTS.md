# Rocket — контекст для нового агента

**Корень проекта:** `Z:\opencode\Rocket`, а не родительский `Z:\opencode`. Это приложение передачи файлов **Windows 10 x64 ⇄ Android 14+**. Начните с [README.md](README.md), затем прочтите [docs/HANDOFF.md](docs/HANDOFF.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/PROTOCOL.md](docs/PROTOCOL.md), [docs/BUILD_TEST.md](docs/BUILD_TEST.md) и [docs/OPEN_ISSUES.md](docs/OPEN_ISSUES.md). `android/README.md` содержит детали телефона.

## Непереговорные требования пользователя

- **Один экран, один сценарий:** на экране только ракета, кнопка «Выбрать файлы» и шестерёнка. Выбрал файлы → появляется слайдер «Поехали!» → провёл вправо → весь UI исчезает, ракета взлетает → после успеха ракета улетает за верхний край, из дыма появляется статистика (файлы, объём, время, средняя скорость). **На ПК и на телефоне одинаково.** Всё остальное (папка приёма, выбор ПК, IP, проверки, брандмауэр) — только в настройках. Не возвращать браузер файлов ПК на телефон, автоотправку сразу после выбора, кучу контролов на главном экране.
- Фиксированные сетевые роли: **ПК — слушающий Go-демон, телефон — инициатор всех TCP-соединений**. Чтобы ПК отправил файл, он помещает ссылку на исходный путь в память; открытый на экране телефон сам опрашивает ПК и скачивает адресованные ему файлы. Адресат определяется сам, когда он один, и выбирается явно, когда их несколько; выбор запоминается.
- Лёгкий Windows EXE на стандартной библиотеке Go и системных DLL, Android на Kotlin и платформенных API без Compose и сторонних runtime-библиотек. **Не добавлять TLS/авторизацию без нового решения пользователя.** Не выдавать CRC32C и публичные ID устройств за защиту; только доверенная локальная сеть.
- Папки по умолчанию: системная Windows Downloads и Android `Download`; выбор другой папки доступен. Никакого `MANAGE_EXTERNAL_STORAGE`. RU/EN автоматически по языку системы.
- **Иконка пользователя** — `assets/icon-source.png`. Все производные (спрайт ракеты, adaptive icon, ICO) создаёт `go run ./tools/genassets`; не подменять иконку другой картинкой и не рисовать ракету заново.
- Отрисовка в нативном ритме дисплея: Android `postInvalidateOnAnimation` + запрос высокой частоты, Windows Direct2D со vsync; **не** фиксированный таймер, статичный экран не перерисовывать непрерывно. Реальные 120 показанных кадров/с на телефонах не измерены; не обещать их без Perfetto.

## Порядок работы при изменениях

1. Сверять факты с кодом: документация фиксирует **текущее** поведение, [OPEN_ISSUES](docs/OPEN_ISSUES.md) — несовершенства.
2. При изменении протокола синхронно менять `internal/wire`, `internal/server`, `android/.../RocketProtocol.kt`, тесты и `docs/PROTOCOL.md`. `list` и произвольный `get` намеренно убраны. Успех исходящего сеанса ПК считает по `offer-done`.
3. UI на ПК и на Android — два воплощения одной сцены (`internal/desktop/scene_windows.go` и `LaunchView.kt`): меняя внешний вид, менять оба. Состояния и тайминги там совпадают намеренно.
4. Проверять `go test -race ./...`, `go vet ./...`, `gradlew.bat :app:assembleDebug --offline --no-daemon`, `android/tests/run-smoke.ps1`. Вид ПК смотреть снимками: `ROCKET_SNAPSHOT_DIR=... go test ./internal/desktop -run TestRenderStates`. Для UX и сети нужны реальные устройства; точные команды и порядок сквозной проверки на эмуляторе — в [BUILD_TEST](docs/BUILD_TEST.md).
5. После изменения пользовательского поведения обновлять README и docs. APK и EXE — собранные артефакты; перед выдачей пользователю пересобрать оба. Не удалять чужие временные данные и настройки без проверки.
6. **Не отправлять в тестах нажатия клавиш или клики в «активное окно»** (`SendKeys`, `mouse_event`): они попадут в чужие программы пользователя. Управлять окном Rocket только сообщениями напрямую в его HWND (`PostMessage`), а экран снимать через `PrintWindow`. В PowerShell не называть свои функции как встроенные псевдонимы (`Move`, `Lp`, …).

## Версии и релизы (GitHub)

- Версия всего проекта — одна строка в `VERSION`. Из неё берут `versionName`/`versionCode` (Gradle), `rocket.exe version` (`-X main.version`) и тег релиза. Не дублировать версию в других файлах.
- `.github/workflows/build.yml`: PR в `main` собирает и тестирует (артефакты exe и apk), **слияние в `main` публикует релиз `v<VERSION>`, если такого тега ещё нет** (текст — `RELEASE_NOTES.md` плюс сгенерированный список PR). Чтобы выпустить релиз, PR должен поднять `VERSION` и переписать `RELEASE_NOTES.md` (первая строка `# Rocket v<версия>`); проверка — `scripts/check-release.ps1`.
- Подпись APK берётся из секретов `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` (создаются `scripts/make-keystore.ps1`); без них релизный APK подписан отладочным ключом. Ключ нигде не хранить в репозитории.
- Локально то же самое делает `scripts/build.ps1` (результат в `dist/`, он в `.gitignore`).
- Репозиторий — `github.com/lemitz/Rocket` (ветка `main`, `gh` авторизован). Первый релиз `v0.2.0` выпущен автоматически слиянием PR и подписан отладочным ключом, потому что секретов подписи в репозитории пока нет (после их добавления удалить релиз и тег `v0.2.0` и перезапустить прогон на `main`, если нужен подписанный). Dependabot открывает PR с мажорными апдейтами (AGP, Gradle, Kotlin, actions): сливать только после проверки сборки.

**Важно при передаче:** проект в Git (`main`), коммиты есть. `git.exe` лежит в `C:\Program Files\Git\cmd` и не в PATH. `android/local.properties` содержит локальный путь SDK (`Z:/SDK`), а `android/app/build/`, `.gradle/` и `rocket.exe` — сборка, не исходники. `cmd/rocket/rocket_windows_amd64.syso` — результат `windres` (иконка и манифест), его нужно пересоздавать при смене `rocket.ico`, `rocket.rc` или `rocket.manifest`.
