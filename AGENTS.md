# Rocket — контекст для нового агента

**Корень проекта:** `Z:\opencode\Rocket`, а не родительский `Z:\opencode`. Это приложение передачи файлов **Windows 10 x64 ⇄ Android 14+**. Начните с [README.md](README.md), затем прочтите [docs/HANDOFF.md](docs/HANDOFF.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/PROTOCOL.md](docs/PROTOCOL.md), [docs/BUILD_TEST.md](docs/BUILD_TEST.md) и [docs/OPEN_ISSUES.md](docs/OPEN_ISSUES.md). `android/README.md` содержит детали телефона.

## Непереговорные требования пользователя

- Одна функция: **выбрать файлы на устройстве-отправителе → выбрать адресата при необходимости → «Поехали»**. Не возвращать браузер файлов ПК на телефон и не запускать отправку сразу после выбора файла. Поиск ПК, IP и папку приёма держать в настройках.
- Фиксированные сетевые роли: **ПК — слушающий Go-демон, телефон — инициатор всех TCP-соединений**. Чтобы ПК отправил файл, он помещает ссылку на исходный путь в память; открытый на экране телефон сам опрашивает выбранный ПК и скачивает адресованные ему файлы. Для двух ПК/двух телефонов адресат выбирается явно и запоминается.
- Лёгкий Windows EXE на стандартной библиотеке Go/встроенных DLL, Android на Kotlin + платформенных API без Compose и сторонних runtime-библиотек. **Не добавлять TLS/авторизацию без нового решения пользователя.** Не выдавать CRC32C или публичные device ID за защиту; только доверенная локальная сеть.
- Папки по умолчанию: системная Windows Downloads и Android `Download`; выбор другой папки доступен. Никакого `MANAGE_EXTERNAL_STORAGE` по умолчанию. UI: синий космос, ракета взлетает во время передачи, по успешному завершению вылетает за верхний край, из дыма появляется статистика файлов/байтов/времени/средней скорости. RU/EN автоматически по языку системы. Пользователь предоставит свою иконку отдельно — не подменять её случайной картинкой.
- Отрисовка в нативном ритме дисплея: Android `postInvalidateOnAnimation` + платформенный high-refresh запрос, Windows Direct2D-present со vsync; **не** фиксированный таймер 30/60/«120 fps». Реальные 120 показанных кадров/с на физических телефонах пока не измерены; не обещать их без Perfetto/замеров.

## Порядок работы при изменениях

1. Сверять факты с кодом: документация фиксирует **текущее** поведение, [OPEN_ISSUES](docs/OPEN_ISSUES.md) — несовершенства. Не путать давно отброшенный проектный черновик Zap/виртуальную расшаренную папку с Rocket.
2. При изменении протокола синхронно менять `internal/wire`, `internal/server`, `android/.../RocketProtocol.kt`, тесты и `docs/PROTOCOL.md`. `list` и произвольный `get` намеренно убраны.
3. Проверять `go test -race ./...`, `go vet ./...`, Android `gradlew.bat :app:assembleDebug --offline --no-daemon` и `android/tests/run-smoke.ps1`; для UX/сети дополнительно нужны два реальных телефона и два ПК. Точные команды в [BUILD_TEST](docs/BUILD_TEST.md).
4. После изменения пользовательского поведения обновлять корневой README и docs. APK и EXE — собранные артефакты, а не исходники; перед выдачей пользователю пересобрать оба. Не удалять чужие временные данные/настройки без проверки.

**Важно при передаче:** `Z:\opencode\Rocket` сейчас не Git-репозиторий; `git.exe` в проверенной Windows-среде не найден. Не предполагать наличие commit history. `android/local.properties` содержит локальный путь SDK (`Z:/SDK`), а `android/app/build/`, `.gradle/` и `rocket.exe` — сборка/локальная среда, не описание исходников.
