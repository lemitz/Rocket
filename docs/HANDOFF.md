## Цель и ожидаемый UX

Rocket — **одна функция: отправить выбранные на своём устройстве файлы на другое устройство локальной сети**. Изначальный интерфейс ошибочно показывал телефону список файлов ПК и заставлял выбирать ПК-файл для скачивания; **это намеренно удалено** (включая серверные `list` и произвольный `get`). Пользователь не должен видеть TCP/UDP, команды, хэши и стадии подтверждения.

| Направление | Что делает отправитель | Что происходит под капотом | Что делает получатель |
|---|---|---|---|
| Телефон → ПК | На телефоне выбирает свои файлы или делится ими из Галереи; при необходимости выбирает ПК один раз; нажимает **«Поехали»** | Android инициирует TCP `put` на ПК, передаёт байты + CRC32C, ПК сохраняет `.part`, проверяет и публикует | ПК уже запущен; входящие файлы появляются в его выбранной папке |
| ПК → телефон | В окне ПК выбирает **файлы на ПК**, онлайн-телефон из списка, нажимает **«Поехали»** | ПК держит в RAM предложения со ссылкой на исходные пути. Открытый на экране телефон опрашивает выбранный ПК, инициирует `offer-get`, сохраняет и подтверждает `offer-done` | Пользователь держит Rocket открытым на выбранном телефоне; **не выбирает файл ПК** |

Два ПК и два телефона предусмотрены: телефон запоминает выбранный ПК, ПК показывает недавно подключавшиеся телефоны (выбор целевого телефона обязателен при ПК→телефон). Без открытого Rocket на телефоне ПК→телефон не запускается. При отправке телефоном в настройках выбирается нужный ПК, но основная кнопка отправки не превращается в файловый браузер.

## Что реально реализовано

- Go-сервер/нативное Windows-окно, CLI для диагностики, UDP-discovery, TCP-передачи `put` и адресных «предложений» ПК→телефон. Окно: выбрать локальные файлы, выбрать телефон, «Launch», поменять папку приёма, анимация/статистика. Роли не меняются при ПК→телефон.
- Android `MainActivity` принимает `ACTION_SEND`/`SEND_MULTIPLE`, выбирает URIs через системный пикер, **подготавливает** метаданные без отправки; запуск только по нажатию «Launch». При активном экране примерно раз в секунду опрашивает выбранный ПК и автоматически принимает адресованные предложения. Настройки ПК/IP и папки приёма скрыты в диалоге.
- Папки по умолчанию: Windows `SHGetKnownFolderPath(FOLDERID_Downloads)` и Android `MediaStore.Downloads` → `Download/`; изменения: Windows GUI/JSON-конфиг, Android SAF `ACTION_OPEN_DOCUMENT_TREE`. На Windows готовый файл публикуется без замены существующего, на Android `IS_PENDING` скрывает незавершённое в Downloads; SAF-публикация зависит от провайдера.
- В обоих приложениях тёмно-синяя космическая тема, рисованная векторная ракета и финальная статистика. UI-строки RU/EN по настройкам ОС; Android также поддерживает системный выбор языка приложения. Иконку пользователь ещё не прислал.
- Сеть без TLS, аккаунта, пароля или реальной аутентификации по явному решению пользователя. `node_id`/`device_id` — публичные метки, не доверенные сертификаты.

## Проверенное и непроверенное

В предыдущем цикле собирались Go EXE и debug APK; `go test -race ./...`, `go vet ./...`, `gradlew.bat :app:assembleDebug --offline --no-daemon` и JVM discovery smoke прошли. На Android API 36 эмуляторе через настоящий GUI ПК были проверены **оба направления**: ПК выбирал локальный README.md и нажимал Launch → Android автоматически принимал его в Download; Android выбирал этот README.md и нажимал Launch → файл появлялся в тестовой папке ПК. Тесты протокола проверяют отказ от старого просмотра папки и изоляцию предложений по заявленным ID. Подробнее — [BUILD_TEST](BUILD_TEST.md).

**Не проверено** на реальных realme GT 6T/Nothing Phone (3a) и двух реальных ПК/телефонах одновременно: Wi-Fi 6, стабильность работы OEM при выборе Share URI, долговременная запись на UFS 2.2, поведение в фоне, фактически представленные 120 кадров/с. Эмулятор API 36 выдаёт 60 Гц; запрос высокой частоты — не доказательство отображения 120 кадров.

## Куда идти дальше

Перед изменениями прочесть [OPEN_ISSUES](OPEN_ISSUES.md) с приоритетами и ограничениями. Важнейшие направления: понятное поведение при отмене/повторном получении предложения; подтверждение результата на **ПК** только после `offer-done`; проверка RU/EN и рендера на реальных устройствах; UX выбора нескольких телефонов, ошибки при долгих/больших файлах; performance-замеры до усложнения конвейера. Не возвращать отображение всех файлов ПК или автоматическую отправку сразу после выбора URI. Новую иконку добавлять **после** получения дизайна от пользователя.
