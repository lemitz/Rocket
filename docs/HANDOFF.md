## Цель и UX

Rocket — **передача выбранных на своём устройстве файлов или короткого текста на другое устройство локальной сети**. Весь интерфейс — один экран:

1. Ракета (вырезана из иконки пользователя), кнопка «Выбрать файлы», шестерёнка. На ПК ещё можно перетащить файлы в окно.
2. После выбора появляются: плашка «N файлов · объём» (касание = выбрать заново, ✕ = сбросить), строка адресата «На …» (касание = выбрать из нескольких, когда нужно) и слайдер **«Поехали!»**.
3. Слайдер вправо (≥85%): весь UI гаснет, ракета взлетает (дрожь, свечение, след, штрихи скорости); снизу тихая подпись «Отправка… 42%» и на телефоне «Отмена».
4. По завершении ракета улетает по оси носа за край, собирается дым, из него появляется карточка «Долетели!»: файлов, объём, время, средняя скорость. «Ок» возвращает ракету. При ошибке — карточка «Не долетели» с причиной, выбранные файлы остаются.
5. Всё остальное — в настройках (шестерёнка): папка приёма, выбор/поиск ПК, адреса, проверки связи и брандмауэра, телефоны.

| Направление | Что делает отправитель | Под капотом |
|---|---|---|
| Телефон → ПК | Выбирает файлы, слайдер | Телефон инициирует TCP `put`, байты + CRC32C, ПК пишет `.part`, проверяет, публикует без перезаписи |
| ПК → телефон | Выбирает файлы (диалог/перетаскивание), слайдер | ПК кладёт в RAM предложения со ссылками на пути; открытый телефон опрашивает ПК, `offer-get`, сохраняет, шлёт `offer-done` |
| Телефон → ПК (текст) | «Отправить текст» → вставляет/набирает либо Share текста → слайдер | `put-text`, Win32 GUI копирует в системный буфер до ACK (не создаёт файл) |
| ПК → телефон (текст) | Копирует текст в другой программе → Ctrl+V в главном окне Rocket → слайдер | RAM-очередь `texts` в `poll`; телефон копирует в системный буфер → `text-done` |

**ПК показывает успех только после `offer-done`** (раньше — после отправки байтов). Телефон и ПК определяют адресата сами, когда он один: ПК берёт единственный онлайн-телефон (и помнит последний в `config.json` → `last_phone`), телефон берёт единственный найденный ПК, а при смене IP заново находит ПК по ID.

## Что реализовано

- **Go (ПК):** сервер, UDP-обнаружение, outbox, нативное окно. Окно теперь рисует **программный растеризатор** (`gfx.go`: сглаженные фигуры, свечение, спрайт, маски текста) в BGRA-буфер; Direct2D только загружает и показывает кадр. Текст — GDI в служебный DIB, маски кэшируются. Манифест включает PerMonitorV2, тёмная рамка через DWM, иконка из ресурсов EXE, `WM_DROPFILES`.
- **Android:** `LaunchView` — вся главная сцена на Canvas (кнопки, слайдер, лист выбора ПК, полёт, карточка); `SettingsPanel` — обычные вью; `MainActivity` — логика (передачи, опрос, автопоиск). Иконка — adaptive (фон `#272733`, ракета, монохромный слой).
- Протокол v1 расширен командами `put-text` и `text-done`, необязательным полем `texts` в `poll`; `list` и произвольный `get` по-прежнему удалены. Статистика файлов подтверждается по `offer-done`, текстов — после копирования/`text-done`. Тексты ограничены 8192 байтами UTF-8 и живут только в RAM; `daemon` без GUI не может принять `put-text`.
- Хранилища и безопасность без изменений: Windows Downloads (`FOLDERID_Downloads`) / Android `MediaStore.Downloads` или SAF-папка; без TLS и авторизации по решению пользователя.

## Проверено и нет

Проверено: `go vet`, `go test -race ./...`, `gradlew :app:assembleDebug`, смоук Android, **сквозные оба направления** на эмуляторе API 36 с настоящим `rocket.exe` (8 МБ и 40 МБ, SHA-256 совпал, статистика на обеих сторонах согласована, `Check now` в настройках телефона), снимки всех состояний ПК (RU и EN, `ROCKET_SNAPSHOT_DIR`), реальное окно ПК (иконка, тёмная рамка, Direct2D, слайдер, полёт, карточка).

Пользователь сообщил, что файловые сценарии на его устройствах **больше недели стабильно работают**; старые заметки о непроверенном железе ниже следует читать как состояние прежнего стенда, а не отрицать опыт пользователя. Для нового обмена текстом выполнены Go-тесты и Android-сборка, **ручной сквозной тест буфера на его реальных устройствах ещё нужен**. Остальные потенциальные ограничения: [OPEN_ISSUES](OPEN_ISSUES.md).

## Куда идти дальше

Реальные устройства и замеры кадров (Perfetto) до усложнения; отмена на стороне ПК и отклонение предложения при отмене; доступность главного экрана Android; решение по службе для приёма без открытого экрана (только с согласия пользователя).
